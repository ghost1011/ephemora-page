The problem

Your agent writes code. That code is untrusted.

Every agentic workflow executes AI-generated code. The three standard options each fail differently.

Containers

~300ms per call, shared kernel, images to manage. Isolation is a config away from none.

Ephemora Cell: 0.125ms pooled, in-process WASM

Subprocesses

No isolation: same user, filesystem, environment. One bad import and everything leaks.

Ephemora Cell: deny-all by default

MicroVMs

~120ms cold start, a whole kernel you don't need. Fine for fleets — absurd per function call.

Ephemora Cell: no kernel, no cloud
Mechanism

Filter → Run → Remove.

Isolated at the WASI layer. Resource-limited. Deterministic. Gone after execution.

Engine Pool

WASM engine caching — no recompile per call. Reuse compiled modules across executions.

Process Worker

Multi-process isolation — concurrent execution with per-worker resource limits.

IO Budget

Rate-limited filesystem access, GC heap control, and per-call timeout. No runaway I/O.

The Cell lifecycle

Born isolated. Consumed by purpose. Gone without a trace.

01

Filter

Only WASM modules cross the boundary. Deny-all preopens — no shell, no syscalls, no ambient authority.

02

Run

Code in, output out. Resource-limited. Deterministic. Same input always yields the same result.

03

Remove

Automatic cleanup. After execution, the sandbox is closed and its working directory removed.

Architecture

Built for scale. Ready for compliance.

Beyond isolation — the internals that make Ephemora Cell production-ready.

Execution Report

Structured, audit-ready execution report per run. Signed with Ed25519 keys and canonicalized per RFC 8785 (JCS). HMAC attestation — not a zero-knowledge proof.
